我做电话开发那阵子，打过大概 2700 通电话，成交 3 单。折算下来，平均每通电话值一块钱。

这个数字本身不丢人。真正让我难受的是另一件事：客户聊到哪一步，我经常想不起来。

同一个客户，Excel 里有一个公司名，微信里是一个昵称，手机通讯录里是一串号码，邮件里又是另一个拼写。上周谁说过什么、报过什么价，得翻三个地方才能拼出来。

那时候我才明白，客户管理系统解决的第一个问题不是“管理”，是“不丢”。

## 外贸客户管理系统到底在管什么？

很多老板以为客户管理就是存名片。存名片当然要，但那只占很小一部分。

我把它拆成三层。

第一层是客户资产。客户的来源渠道、公司信息、联系人、决策人、当前阶段、历史报价、订单记录。换一个业务员接手，打开就能看到这个客户发生过什么。

第二层是销售动作。今天该跟谁、上次聊到哪、下一步做什么、有没有别人在跟同一个客户。没有这一层，客户再多也只是躺在表里。

第三层是经营数据。线索进来多少、转成客户多少、进了商机多少、报价后成交多少。没有这一层，管理者只能凭感觉判断业务好坏。

| 模块 | 解决什么问题 | 没有它会怎样 |
|---|---|---|
| 客户档案 | 客户身份和历史统一 | 换人接手就断档，同一客户被重复开发 |
| 跟进记录 | 上次聊了什么、下一步是谁 | 每次打电话都从“您好，请问您做外贸吗”重新开始 |
| 客户分级 | 资源优先给值得的客户 | 业务员把时间平均分给所有人，A 类客户反而被冷落 |
| 商机与报价 | 推进过程可追踪 | 报价发出去没有回音，也不知道卡在哪一步 |
| 单据与回款 | 业务、跟单、单证对齐 | 订单和客户对不上，出了问题互相找 |
| 提醒与待办 | 跟进节奏不靠记性 | 客户凉了才发现一个月没联系 |

## 从 Excel 到系统，第一步不是买软件

我见过最常见的错误，是流程还没定就先买一套系统。结果大家把原来表格里的混乱原样搬进去，只是多了一个登录入口。

真正该先做的，是清洗。

1. 把散在各处的客户拉出来：Excel、微信、邮箱、手机通讯录，先不管格式，全部并到一张总表。
2. 给每条记录一个不会重复的标识，通常用公司全称加国家，不要用简称。
3. 合并重复客户。这一步最花时间，同一个客户可能被不同业务员录过三遍。
4. 补上最近联系时间。超过半年没联系的单独标出来，这批客户要么重新激活，要么先放一边。
5. 定当前阶段：新线索、已联系、有需求、已报价、已成交、复购中。
6. 给每条记录写一个下一步动作和日期，写不出来就说明这条记录还没准备好。
7. 跑两周再决定要不要导系统。两周后还在用的字段留下，没人填的砍掉。

第一次合表的时候，光是把“公司名”对上就花了一晚上。有的写全称，有的写简称，有的只写了老板的姓。合完之后我才知道，我以为的客户数量，其实有一截是重复的。

## 一张客户表该有哪些字段？

字段不是越多越好。我的原则是：没有字段对应一个下一步动作的，先别加。

| 字段 | 必填 | 示例 | 作用 |
|---|---|---|---|
| 公司全称 | 是 | 河北某紧固件有限公司 | 作为主键，避免重复 |
| 来源渠道 | 是 | 展会、平台、电话、转介绍 | 判断哪个渠道值得继续投入 |
| 联系人 | 是 | 采购经理、老板 | 知道找谁、谁拍板 |
| 国家地区 | 是 | 阿联酋、波兰 | 区分时区、语言和需求 |
| 主营产品 | 否 | 紧固件、丝网、集成房屋 | 判断匹配度 |
| 当前阶段 | 是 | 已报价、待样品 | 决定跟进动作 |
| 最近联系时间 | 是 | 2026-11-16 | 发现被晾太久的客户 |
| 下一步动作 | 是 | 下周三前发样品报价 | 让跟进有落点 |
| 负责人 | 是 | 业务员或经理 | 避免撞单、方便交接 |

如果只能留五个字段，我会留公司全称、来源、阶段、最近联系时间、下一步动作。这五个字段能回答一个最基本的问题：这个客户现在值不值得跟，下一步该做什么。

## 自建还是买 SaaS？

这个问题我被问过很多次。我的答案通常不讨喜：先看你的流程有没有稳定下来。

| 维度 | 买 SaaS | 自建 |
|---|---|---|
| 上线速度 | 一周内能用 | 至少一个月起，看需求 |
| 成本结构 | 按账号按年付费，前期轻 | 开发、服务器、维护都要算 |
| 灵活性 | 只能按厂商的流程改 | 想怎么改就怎么改 |
| 维护 | 厂商负责 | 自己找人，或者自己上 |
| 数据归属 | 要确认能完整导出 | 数据在自己手里 |
| 适合谁 | 小团队、流程还在试 | 流程稳定、要跟单据财务打通 |

我的经验是：团队五个人以内、流程还在试，先用现成的或用表跑。等客户量上来、开始有业务员离职交接、单据和客户老对不上，再考虑行业系统或者自建。

自建也不是万能。我自己写过一套销售小工具，最早只是几个 CSV 加脚本，后来越加越多，数据格式不统一，迁移的时候在电脑前坐了两个晚上。工具能自建，维护成本是另一回事。

## 选型时我会问哪五个问题？

1. 客户数据能不能完整导出？导出格式是什么？这决定了你以后能不能走。
2. 阶段和字段能不能按我们的流程改？改不了就要让业务去适应软件。
3. 要不要和报价、订单、单据、回款打通？只做客户管理，和做业务全流程，是两套选型逻辑。
4. 谁负责维护？没有内部负责人，系统上线三个月就会变成另一个没人看的表。
5. 一年后会有多少人用？只看老板和销售，还是跟单、单证、财务都要进来？人数决定权限和培训成本。

顺便说一句，工具只是工具。同样一套系统，有的团队用成了客户资产，有的团队用成了打卡软件。差别不在软件，在有没有人真的按它干活。

## 系统上了，人不用怎么办？

这是客户管理里最难的一步，比选型难。

我的做法是把录入挂在已有动作上，而不是额外加一个动作。

打完电话，顺手写三行：客户说了什么、他关心什么、下一步是什么。

发完报价，把报价日期和金额记上，约定回访时间。

每周五下午，经理只看一个指标：有多少客户超过两周没有联系。不看填得多完整，先看有没有断。

字段先砍到最少，允许记录不完整。业务员最烦的是填表，第二烦的是重复填表。系统里已经有的信息，不要再让人填一遍。

## 最后

客户管理系统的价值，不是把客户关进一个软件里，是让下一个接手的人知道：这个客户是谁，我们聊到哪，下一步该做什么。

如果这三点做不到，再贵的系统也只是另一个 Excel。
