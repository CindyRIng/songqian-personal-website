Fuma はチームが毎日使う CRM です。Web コンソールは人が 1 アカウント・1 タブで使う前提で、API も SDK もありません。顧客一覧、オープンシー、重複チェック、通関データは、その画面の中にしかありません。

fuma-platform はその上に薄く載せたローカル基盤です。業務ロジックを作り直すのではなく、Web コンソールをローカルでプログラマブルな機能群に変え、他のシステムやエージェントから呼べるようにしました。

## ローカルの事実を先に

書き込みはまず SQLite のトランザクションと outbox に入り、非同期で上流へ同期します。上流と食い違えば、黙って上書きせず差異を記録します。呼び出し側は常に確定したローカルの事実を得ます。

## 1 つのレジストリ、4 つの入口

43 の機能を一度だけ定義し、CLI・REST v1（Fastify、ループバック + Bearer）・MCP stdio・SKILL を生成します。CLI だけにある機能は存在しません。`npm run spec` が同じ定義から OpenAPI と CLI/MCP 契約を出します。

## 難しかったのはセッション

ログインは DingTalk SSO の QR コード。トークンは AES-256-GCM で暗号化し、心拍で延命、24 時間で再ログイン待ち行列へ。リクエストプールはアカウント単位で直列化し、QPS 制限とジッタをかけます。ブラウザはログイン時だけ起動します。

## 学んだこと

レジストリこそが製品でした。定義が 1 つなら、4 つの入口は 4 つの保守対象ではなくなります。未確認の上流契約などの制限も README に正直に書く。それが一番安い設計判断でした。
