Tanji は開拓（プロスペクティング）プラットフォームです。企業を検索し、条件で絞り、登記・株主・主要人物を読み、枠を使えば連絡先も取れます。ブラウザでは本当に強力で、プログラムからは本当に厄介です。ログインは SSO cookie に依存し、頻繁なリクエストは制限され、ページ API は変わり、同じアカウントを共有する複数スクリプトは同じブラウザプロファイルを奪い合います。

tanji-client はそれらを 1 つのローカル owner プロセスに収束させます。ブラウザ、REST サービス、キャッシュ、レートリミッタ。CLI、MCP、スクリプトはローカル REST とだけ話し、自分ではブラウザを開きません。

## 1 つの owner、複数のアカウント

アカウントごとにプロファイル、キャッシュ、ポートを持ちます。ブラウザを所有するのは常駐サービスのみ。MCP は既定で REST へ代理するだけでプロファイルを持たないため、「already running」のロック問題が消えます。ログインは電話番号とパスワード → SSO → 開拓製品。アカウントセンターは生きているが製品セッションが切れている中間状態も明示的に回復します。CAPTCHA は可視ブラウザにフォールバックします。

## フィルタはデータ

検索面には 12 カテゴリ、345 の詳細フィルタ条件があります。フォームをハードコードせず、同じ源から生成したフィルタレジストリを同梱し、フィルタファイルを受け付けます。高度な絞り込みは UI ではなくデータの問題になります。

## レート制限は製品設計

開拓は枠で課金されるので、節約自体が機能です。企業詳細は軽量モードで呼び出しを減らし、アンロックは既定で上流 1 回。リミッタは priority（アンロック・ログイン）と bulk（読み取り）の 2 チャネルで、長いバッチがアンロックを塞ぎません。キャッシュは TTL 付き cache-aside で、ヒットは約 1〜2 ミリ秒。真実が必要なときのクリアコマンドもあります。

## インターフェースと誠実さ

13 の MCP ツール、操作ごとのドキュメント付き CLI、OpenAPI の REST、エージェント向け SKILL、そして 59 の vitest ケース。README には実際の制限が書かれています。キャッシュに LRU はなく、一部のキーは並び順を無視し、アンロックは枠を消費する——だから明示的な確認フラグが必要です。ライセンスは Unlicense（パブリックドメイン）。

## 学んだこと

マルチアカウントのシステムは、機能の問題である前に分離の問題です。レート制限は API と一緒に設計すべきで、最初のアカウントが止まってから後付けするものではありません。そして上流が変わり続ける Web であるなら、アダプタ層こそ保守時間の予算を置く場所です。
