外呼是销售工作里「话变成数据」的地方，也是数据最容易丢的地方。飞鸽的网页端能看话单、听录音、拨号，但录音只保留一段时间，转写覆盖不全，没有 API、没有回调。想让脚本或 Agent 对一通电话做点什么，得有个开着浏览器的人一直守着。

## 问题

我把外呼拆成三件事：拨出去、把话单和录音留下来、把录音变成可读的文字和分析。三件事上游都只给了网页入口。还有两个现实问题：登录态 7 天会过期，阿里云滑块很难自动；历史话单散在网页里，录音过了窗口期就没了。

## 做法

FOP（feige-outbound-platform）是一个常驻本地的平台。北向四个入口：REST v1（Fastify，仅回环 + Bearer，OpenAPI 3.1 + Swagger）、CLI、MCP stdio、SKILL。南向做自动化：多账号自动登录（含滑块）、7 天 JWT 保活、话单增量与全量同步、回拨呼出的排队状态机。

最重要的是「录音不再消失」：话单同步时下载录音，按 sha256 归档成 WAV，按年/月/日存好；然后 100% 在本地转写。

## 架构要点

- 本地转写：MiniMax asr-1.0。实测录音是 8kHz 双声道，销售和客户各占一个声道——拆开声道就得到说话人分离，比靠 diarization 猜可靠。长通话在静音点切块，分块结果缓存，失败重试可断点续跑；词表负责把公司名的九种同音误听归一。
- AI 后处理：DeepSeek 固定 prompt + JSON schema，校验失败沿升级链重试，输出摘要、意图、关键词、行动项、风险与质检建议。
- 存储与运行：SQLite WAL（15 张表）+ WAV 归档 + SSE 事件 + 可恢复作业队列；systemd 常驻，无显示环境用 Xvfb 登录。

## 学到什么

93/93 单测、27/27 验收通过。诚实写限制也重要：上游没有 SIP 线路，真实呼出是回拨模式，坐席手机要先接听；v1 不做 AI 语音外呼；默认账号的 ASR 并发是 1，全量回补会很慢。这些我都写在 README 里。

最大的收获是「数据所有权」：当录音和转写都落在自己机器上，销售过程才第一次变成可以查询、可以复盘的东西。
